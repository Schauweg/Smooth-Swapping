# Configurable modded screen compatibility

Date: 2026-06-24
Branch: modded-container-compat

## Review direction

The PR review asked for the mod logic to avoid per-mod hardcoded screen or handler classes. The
compatibility layer is now data-driven: Smooth Swapping reads a configured list of supported modded
screens and applies a small set of generic slot policies.

Auto-detection is intentionally left as future work. It would need loader- and mod-specific runtime
checks, while the current review request can be satisfied with an editable preconfigured list.

## Config file

The file is the existing Smooth Swapping config:

`config/smoothswapping.json`

The config is generated by the existing common `ConfigManager`. No new config library was added.
The built-in default entries live in
`common/src/main/resources/assets/smoothswapping/default_modded_screen_compatibility_entries.json`,
so adapter and registry logic do not contain per-mod class lists.

## New fields

`modded_screen_compatibility_enabled`

- Global switch for configured modded screen entries.
- Default: `true`.
- Vanilla/default behavior is separate and remains handled by `VanillaLikeScreenAdapter`.

`modded_screen_compatibility_entries`

- Editable list of configured entries.
- Defaults are written when the config is first generated.
- If a user removes an entry from the JSON list, it is not reinserted on every startup.
- If the whole config file is deleted or reset, defaults are generated again.

Each entry supports:

- `id`: human-readable identifier.
- `enabled`: per-entry switch.
- `screen_classes`: full screen class names to match.
- `menu_classes`: full container/menu/screen-handler class names to match.
- `slot_policy`: currently `vanilla_like`, `configured_item_slots`, or the alias
  `real_item_slots_only`.
- `item_slot_classes`: real item slot classes for `configured_item_slots`.
- `include_player_inventory_slots`: whether player inventory slots should be included.
- `player_inventory_slot_classes`: player inventory slot classes accepted when the previous flag is
  enabled.
- `click_animation_window_ms`: optional click timing guard. Use `-1` to disable.
- `max_changed_slots`: optional changed-slot guard. Use `-1` to disable.

## Default entries

### Macaw's Furniture

Entry id: `macaws_furniture`

Screen classes:

- `net.kikoz.mcwfurnitures.storage.FurnitureScreen`
- `com.mcwfurnitures.kikoz.storage.FurnitureStorageScreeen`

Menu classes:

- `net.kikoz.mcwfurnitures.storage.FurnitureScreenHandler`
- `com.mcwfurnitures.kikoz.storage.FurnitureStorageContainer`

Slot policy: `vanilla_like`

### MrCrayfish's Refurbished Furniture

Entry id: `refurbished_furniture`

The default list includes the common Refurbished Furniture screens plus the Fabric and NeoForge
cooking screen variants audited earlier. The entry uses `vanilla_like` because the menus follow the
normal `AbstractContainerScreen` / `AbstractContainerMenu` pattern.

### Traveler's Backpack

Entry id: `travelers_backpack`

Screen classes:

- `com.tiviacz.travelersbackpack.client.screens.BackpackScreen`

Menu classes:

- `com.tiviacz.travelersbackpack.inventory.menu.BackpackItemMenu`
- `com.tiviacz.travelersbackpack.inventory.menu.BackpackBlockEntityMenu`

Slot policy: `configured_item_slots`

Real item slot classes:

- `com.tiviacz.travelersbackpack.inventory.menu.slot.BackpackSlotItemHandler`

Player inventory slots:

- `include_player_inventory_slots`: `true`
- `player_inventory_slot_classes`: `net.minecraft.world.inventory.Slot`

Safety guards:

- `click_animation_window_ms`: `1000`
- `max_changed_slots`: `12`

This keeps the conservative behavior from the tested implementation without keeping a
Traveler-specific Java adapter. Tool slots, upgrade slots, fluid slots, filter/fake slots, disabled
slots, crafting slots, and result slots are skipped because they are not listed as real item slot
classes.

## Editing examples

To disable one default entry, set:

```json
"enabled": false
```

To remove support for a default entry, delete that object from
`modded_screen_compatibility_entries`.

To add a vanilla-like screen:

```json
{
  "id": "example_mod",
  "enabled": true,
  "screen_classes": [
    "com.example.client.screen.ExampleScreen"
  ],
  "menu_classes": [
    "com.example.inventory.ExampleMenu"
  ],
  "slot_policy": "vanilla_like",
  "item_slot_classes": [],
  "include_player_inventory_slots": false,
  "player_inventory_slot_classes": [],
  "click_animation_window_ms": -1,
  "max_changed_slots": -1
}
```

To add a screen with only specific real item slots, use `configured_item_slots` and list the slot
classes that should animate.

## UI note

The existing Mod Menu / NeoForge config screen is focused on the animation toggle, speed, and curve
editor. It does not currently expose list editing for configured modded screens. The JSON file is the
supported editing surface for this compatibility list.

## Manual test checklist

1. Start with only Smooth Swapping and required loader dependencies.
2. Test vanilla inventory, chest, barrel, shulker box, hopper, furnace, and crafting table.
3. With default config unchanged, test Macaw's Furniture storage furniture normal click, shift-click,
   and player inventory transfer.
4. With default config unchanged, test Refurbished Furniture containers normal click, shift-click,
   and player inventory transfer.
5. With default config unchanged, test Traveler's Backpack main storage normal click, shift-click,
   and player inventory transfer.
6. Disable or remove one configured entry and confirm the game does not crash. That screen should no
   longer use its configured compatibility policy, though it may still fall back to vanilla-like
   behavior if the screen is simple enough.
7. Add a new vanilla-like screen/menu class pair to the JSON and confirm it matches.
8. Start without any of the preconfigured mods installed and confirm the client does not crash.
